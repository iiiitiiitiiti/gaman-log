# 008: Claude Code が終わる前に試験とビルドを通させる（Stop フック）

- 日付: 2026-10-20
- 状態: 試行

## 決めたこと

このリポジトリで Claude Code が作業を終えようとしたとき、`.claude/hooks/stop-verify.sh` が `npm test` と `npm run build` を流す。落ちたら失敗の出力を Claude へ返し、直すまで終わらせない。設定は `.claude/settings.json` にあり、このリポジトリを開いたときだけ効く。

- 型チェックは `npm run build` の `tsc -b` が兼ねるので、`npm run lint` は流さない
- 前回通った状態から変わっていなければ流さない。変わったのが `docs/` と `*.md` だけのときも流さない。質問に答えるだけのターンで待たせないため
- 同じ失敗が2回続いたら止めるのをやめる。5回止めても通らないときも同じ。止めるのをやめたときは画面にその旨を出す
- 試験の数が減っていたら1回だけ指摘する。消した理由が正当かは機械では判定できないので、止め続けはしない
- 判定できないとき（`jq` や `node_modules` が無いなど）は止めない
- 状態は `.git/stop-verify/` に置く（リポジトリには入らない）

## 理由

yomiyasu の作者が「完成の条件を先に決め、満たすまでエージェントを回す」仕組みで改善を速く回していると知った（2026-10-20）。ユーザーが4案から一番小さい Stop フック方式を選び、このアプリで試すことにした。

| 案 | 採らなかった理由 |
|---|---|
| `claude -p` を外のスクリプトで繰り返す | 毎回新しい会話になり、途中の経緯の引き継ぎが要る。まず1つの会話の中で試す |
| 複数のエージェントで作る・確かめる・直すを分ける | 使用量が大きく増える |
| GitHub の自動テストが落ちたら直させる | push の後にしか効かない。push の前に止めたい |
| ユーザー全体の設定に置く | 試験の無いリポジトリや文章だけの作業まで止まる |

## やらないこと

- 見た目の確認（撮影・計測）はループに入れない。好みの判断は人が見る
- `npm run lint` を別に流すこと（build と同じ型チェックになる）
